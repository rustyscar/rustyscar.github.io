rccheck — RC 結構圖說配筋反推檢核工具

讀取 CAD 結構圖說 → 萃取配筋 → 反推承載荷重 → 與法規需求比對 → 篩查設計疏失
實作計畫說明 ｜ 2026/06/10 ｜ 示範案：11304Y（嘉義南門段店鋪集合住宅，地下4層＋地上15層＋屋突）
⚠ 定位聲明：本工具為篩查（screening）輔助工具，所有反推結果與 DCR 異常項目均為「需要人工查證的線索」，不得作為施工或送審之最終結論，須由負責結構技師覆核。此聲明將固定置於所有輸出報告之頁首。

一、背景

結構圖說中的配筋量隱含了設計時採用的載重。若能由配筋反推各構件（梁／柱／版／牆）實際可承受的荷重，再與「依平面幾何與法規載重推算的需求」比對，即可系統性地篩出兩類異常：

  • 偏低配筋承載力低於法規需求 → 可能為設計疏失（漏算載重、圖載不符、抄錯配筋）。
  • 偏高承載力遠高於需求 → 可能為過度設計，或圖面與計算模型不一致，亦值得查證。

本案以 11304Y\1150610 圖說為示範開發第一版，但架構自始即為多案件、多設計單位圖風的擴充而設計。

二、分析

2.1 資料現況盤點（已實際探查確認）

關鍵發現：S 編號圖紙檔只是 XREF 殼（僅 80–260KB），實際圖形內容集中於四個大檔。解析工作應直攻大檔，殼檔僅用於「圖紙歸屬對帳」。

2.2 各類構件的圖面表達格式（已比對 PDF 確認）

構件表達方式實例（取自圖面）解析難度
梁逐根展開立面圖：標題＝樓層＋梁名＋斷面，配筋文字散佈於梁圖周邊，需空間關聯B3F BB-2 (60x70)、4-#10（主筋）、2-#4 (EF)（腰筋）、17-#4@15（箍筋）中
柱表格式：柱號／斷面／主筋／箍筋／樓層分段12-#8、#4@10、樓層分段低
版／牆平面標註式＋區域邊界，標註分散D16@150 雙向、豎筋／橫筋高
平面圖梁柱牆位置、編號、跨距標註（cm）與 DIMENSION 實體、版厚跨距 680、1170…中
S001 一般說明材料強度表＋設計載重文字段fc' 280／350／420 kgf/cm²、SD420W／SD280、內政部 RC 規範＋ACI 318中（半自動）

※ 梁長度的取得：主來源＝平面圖跨距標註與 DXF DIMENSION 實體（內含實測值）；輔來源＝配筋立面圖內局部尺寸（如箍筋加密區長度）。配筋定義與平面實例以（樓層, 編號）連結後，每根梁同時具備配筋＋斷面＋跨長。

2.3 技術選型

環節採用方案理由／備註
DWG 讀取ezdxf 1.4.4 ＋ ODA File Converter皆免費；統一轉成 DXF R2010（UTF-8）避開 CP950 中文編碼問題。本機已安裝（ODA 27.1.0），路徑採彈性解析：設定檔 → 環境變數 → 自動掃描 Program Files\ODA\，換機器不需改程式。
表格／文字萃取ezdxf（TEXT／MTEXT／INSERT 遞迴／ACAD_TABLE／DBSCAN 聚類）API 完整；不足處自寫空間關聯演算法。
斷面強度concreteproperties（MIT, PM 曲線）＋ 自寫公式雙軌互驗無台灣規範內建 → 以自建法規參數層套用。
不採用AutoCAD COM（中文支援差）、LibreDWG（寫入受限、中文待確認）、Aspose.CAD（商業授權）調查後排除。
現成開源工具經 GitHub／文獻調查，未找到可直接使用的「配筋圖反推荷重」工具 → 解析層自行開發。

三、結論 — 系統架構與流程

3.1 四層分離架構

核心設計是「中性構件模型」這道防火牆：解析的混亂被擋在 adapter 層，計算層只讀中性模型、完全不碰 DXF。新的設計單位圖風＝只新增一個 adapter；新的構件類型＝型別開放式註冊，架構不動。

橫切關注：perf.py 計時儀表自第一個腳本起記錄「每階段 × 每檔」耗時入庫，於報告呈現，供後續各腳本效能優化。

3.3 反推檢核邏輯（核心方法論）

各構件方法：梁＝上述流程；柱＝concreteproperties 建 PM 曲線 ＋ 上方樓層 tributary 軸力累計（活載折減規則參數化，待確認）；版＝單向／雙向彎矩係數法比對 As；牆＝最小鋼筋比（ρv、ρh）＋剪力概算。側力主控構件（連接梁 CG、剪力牆）標示「重力法不適用，僅供參考」。

假設條件均逐構件記錄於報告：所用彎矩係數、tributary 假設、載重假設版本、法規版本（code_version）。

3.5 分階段里程碑

M1
大梁切片（最小可驗證） — 轉檔＋標註文法＋梁立面解析（標題錨定），範圍限 B1F~3F 大梁，輸出配筋 CSV。perf 計時自此啟用。
驗證：抽 30 根逐欄比對 PDF（S401~S423），欄位正確率 ≥95%、標題覆蓋率 100%、中文無亂碼、各階段耗時統計。
M2
全構件萃取＋連結 — 全樓層大小梁、柱表、S001 材料、平面圖（跨距／版厚／梁實例）、linker＋孤兒報告、SQLite 入庫。
驗證：覆蓋率三角對帳（標題偵測數 vs 殼檔反查 vs PDF 目視點數）；孤兒清單人工檢視。
M3
梁反推檢核端到端 — 容量計算、反推 wu,supply、需求 wu,demand、荷重比較＋DCR、Excel 報告；載重假設表人工確認後入庫。
驗證：任選 5 根梁附完整手算書（公式／單位／假設逐列）比對，誤差 <1%；wu 分布 sanity check。
M4
柱＋規則檢核 — PM 曲線（concreteproperties）＋樓層軸力累計＋ρ／箍筋間距規則；法規版本插件第二版（舊法載重組合）。
驗證：3 支柱 PM 曲線與試算表交叉比對；φ 對應差異說明文件。
M5
版牆＋整合輸出＋擴充演練 — 版牆解析（含人工 CSV 補登通道）、HTML 整合報告、DXF 異常標註疊圖、計算書匯入介面雛形；以第二案件演練 adapter 移植。
驗證：第二案移植紀錄（需改動點回饋介面設計）；整合報告含覆蓋率／confidence／待確認清單。

3.6 驗證策略（貫穿各里程碑）

  • Golden set：人工自 PDF 抄錄 50~100 個構件為標準答案，pytest 逐欄比對，任何解析改動皆有迴歸保護。
  • 覆蓋率三角對帳：標題偵測數、圖紙殼反查涵蓋數、PDF 目視點數，三者一致才算完整。
  • Confidence 分層抽驗：低信心構件 100% 人工檢視，高信心隨機抽 10%。
  • 計算雙軌：自寫公式 vs concreteproperties 互驗。
  • 一致性規則：ρmax 超限、箍筋間距異常等自動標紅——既是解析錯誤偵測器，也可能正是要找的設計疏失。

3.7 風險與緩解

風險緩解
CP950 中文亂碼（R2004 DWG）統一轉 R2010（UTF-8）＋轉檔後自動健檢
文字藏在圖塊（INSERT）內虛擬實體遞迴展開＋座標轉換（不修改原檔）
不同設計單位圖風差異adapter registry＋案件 YAML；文法／空間層共用；M5 以第二案實測
版牆平面標註解析難度高排後期＋人工 CSV 補登通道（計算層不在乎資料來源）
彎矩係數法不適用情況（不等跨、側力主控）逐構件標示假設；側力主控構件標「僅供參考」；門檻保守化；全案須技師覆核
截斷筋／搭接多重標註全部保留＋flag，容量取保守組合
S001 載重段解析不全半自動：程式抽段、人工確認入庫，未確認標「待確認」
法規版本差異（新舊案）法規參數全收斂於 codes 插件，案件設定檔指定版本

四、建議

  1. 立即執行 M1：範圍刻意縮小（轉檔＋大梁萃取＋人工比對），用第一批真實錯誤型態校準後續工作量估計——空間關聯的實際難度需看過實際錯誤分布才能確定。
  2. 執行環境：Windows 10、Python 3.13；相依套件 ezdxf、pydantic、concreteproperties、numpy、jinja2、openpyxl、pytest；另需 ODA File Converter（免費，路徑由程式自動偵測或設定檔指定）。
  3. 人工確認節點（必要，不可省略）：① S001 設計載重表確認入庫；② M1 抽樣 30 根比對；③ 低信心構件逐筆檢視；④ 最終 DCR 異常清單由結構技師覆核。
  4. 數值計算輸出一律附公式、單位（kgf-cm 制）與假設條件；未確認資訊標示「待確認」。
